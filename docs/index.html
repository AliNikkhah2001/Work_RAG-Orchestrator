Work RAG Orchestrator

LangGraph orchestration and public OpenAI-compatible chat API for the Work Credit RAG platform. Implemented and live on Vast.ai (main). The runtime matches the deployed system and includes the ambiguity resolver, clarifying-question generator, and metadata (subspace) filtering layers.

1. Summary

The Orchestrator owns request coordination. It receives a chat completion request, runs it through a deterministic LangGraph workflow, and returns a grounded, citation-shaped response.

The graph is deterministic and classifies every turn before retrieval so greetings, subspace specifications, and real questions each take the right path. It never calls Gemma directly — generation is delegated to Guardrails (POST /v1/chat/completions → Gemma :18000).

Status

Implemented & live Vast.ai main. Compiled with MemorySaver; exports rag_graph and graph (Studio entry point in langgraph.json → studio_graph.py:graph).

Deterministic LangGraph flow. Entry is validate_input (nodes/validate_input.py:13, calls Guardrails POST /v1/rails/check via clients/guardrails.py:91). should_continue_after_validation (graph.py:24) sends blocked turns to format_refusal → End and allowed turns to classify (nodes/classify.py:67, calls Guardrails /v1/chat/completions via clients/guardrails.py:135). should_route_after_classify (graph.py:31) routes greeting/specification to format_response → End, question-with-hybrid to hybrid_classify (nodes/hybrid_classify.py:67, SVM-RBF with Gemma escalation) → retrieve, and question-without-hybrid directly to retrieve (nodes/retrieve.py:851, calls KB POST /search/api via clients/knowledgebase.py:61). should_clarify (graph.py:45) splits retrieve into generate_clarification → End (needs clarification, calls Guardrails /v1/chat/completions) or build_context → guarded_generate → format_response → End (continue; guarded_generate at nodes/guarded_generate.py:16 calls Guardrails /v1/chat/completions → Gemma). format_refusal is registered as a second alias of format_response (graph.py:109).

Validated against src/work_rag_orchestrator/graph.py: validate_input → (blocked → format_refusal → End | allowed → classify) → (greeting/specification → format_response → End | question → hybrid_classify → retrieve | question → retrieve when hybrid disabled) → retrieve → (needs clarification → generate_clarification → End | continue → build_context → guarded_generate → format_response → End).

6. Tracing (Langfuse)

Every request creates a trace keyed by X-Request-ID with spans: validate_input, classify, query-rewrite, retrieve (+ retrieve-supplement-fallback, retrieve-dlq, retrieve-retry, retrieve-broadened), build_context (+ compact), guarded_generate, format_response / generate_clarification, and a final trace-create upsert with output and metadata (citations, latency_ms, finish_reason). Falls back to the local JSONL collector at :3000 when Langfuse :3001 is unavailable. View via GET http://127.0.0.1:3000/observe/{request_id} or Langfuse UI :3001.
