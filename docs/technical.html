Deterministic LangGraph flow. Entry is validate_input (nodes/validate_input.py:13, calls Guardrails POST /v1/rails/check via clients/guardrails.py:91).

  • should_continue_after_validation (graph.py:24) sends blocked turns to format_refusal → End and allowed turns to classify (nodes/classify.py:67, calls Guardrails /v1/chat/completions via clients/guardrails.py:135).
  • should_route_after_classify (graph.py:31) routes greeting/specification to format_response → End; question-with-hybrid to hybrid_classify (nodes/hybrid_classify.py:67, SVM-RBF with Gemma escalation) → retrieve; question-without-hybrid directly to retrieve (nodes/retrieve.py:851, calls KB POST /search/api via clients/knowledgebase.py:61).
  • should_clarify (graph.py:45) splits retrieve into generate_clarification → End (needs clarification, calls Guardrails /v1/chat/completions) or build_context → guarded_generate → format_response → End (continue; guarded_generate at nodes/guarded_generate.py:16 calls Guardrails /v1/chat/completions → Gemma).
  • format_refusal is registered as a second alias of format_response (graph.py:109). Compiled with MemorySaver; exports rag_graph and graph (graph.py:166-168).

Conditional edges

  • should_continue_after_validation(state) → "format_refusal" if blocked else "classify" (graph.py:24)
  • should_route_after_classify(state) → "format_response" if classify in ("greeting","specification") else "hybrid_classify" (when hybrid_classifier_enabled) else "retrieve" (graph.py:31)
  • should_clarify(state) → "clarify" if needs_clarification or the T5 scattered/ambiguity safety net fires; else "continue" (graph.py:45)

Supplemental entity rows short-circuit clarify: when the entity tool matched a dictionary, the model can answer directly, so clarification is suppressed. should_clarify also checks subspace_ambiguity_route and ambiguity_ambiguous (gated by settings) and falls back to is_scattered_ambiguous from nodes/infer_specification as a safety net.

Compiled with MemorySaver (dev checkpointer); exports rag_graph and graph (Studio entry point in langgraph.json → studio_graph.py:graph). format_refusal reuses format_response registered as a second alias (graph.py:109).

4. State (RAGState)

Carried through the graph:

  • Core: request_id, messages, query, rewritten_query, guardrail_decision, blocked, refusal_message, retrieved_chunks, prompt_messages, answer, citations, formatted_response
  • Classification/subspace: classify, applied_subspace, sticky_subspace, needs_clarification, clarifying_question, available_subspaces, filter_path, injected_entities, supplemental
  • Greeter/FAQ: greeting_only, direct_faq_answer, faq_matched, faq_verified
  • Timing/fallback: stage_timing_ms, fallback_used, fallback_reason, broaden_used, error, follow_ups
  • Ambiguity: ambiguity_score, ambiguity_margin, ambiguity_entropy, ambiguity_ambiguous, ambiguity_source, subspace_sims

record_timing(state, stage, elapsed_ms) centralizes stage-timing bookkeeping (state.py).

6. API contract

MethodPathPurpose
GET/healthProcess health {"status":"ok"}
GET/readyDependency readiness for KB + Guardrails; ready only when both ready
GET/v1/modelsModel discovery (ics-helper-agent)
POST/v1/chat/completionsOpenAI-compatible chat entry point (streaming + non-streaming)

Request (POST /v1/chat/completions)

{
  "model": "gemma-4-31b",
  "messages": [{"role":"user","content":"چگونه می‌توانم گزارش اعتباری خود را دریافت کنم؟"}],
  "max_tokens": 500,
  "temperature": 0.0,
  "stream": true,
  "filter_path": "گزارش اعتبارسنجی چک"
}

Non-streaming response includes rag metadata (request_id, citations, applied_subspace, available_subspaces, supplemental, follow_ups) and an optional audit trail. Streaming returns SSE data: chunks ending with data: [DONE]; the final chunk carries rag metadata and finish_reason (stop, content_filter, or clarify). Graph failure → 500 {"detail":"Orchestration failed"}; unhandled exception → 500 {"detail":"Internal server error"}.

The API layer restores sticky applied_subspace from the LangGraph MemorySaver checkpoint, and — because Open WebUI sends no X-Request-ID (new thread per turn) — mines sticky from the user-only chat history (interrogatives skipped, so only declarations set scope). T4 injection applies the sticky filter_path for generic follow-ups; B sticky decay drops the subspace after sticky_decay_turns (default 3) consecutive generic turns.

7. Tracing (Langfuse)

Every request creates a trace keyed by X-Request-ID with spans: validate_input, classify, query-rewrite, retrieve (+ retrieve-supplement-fallback, retrieve-dlq, retrieve-retry, retrieve-broadened), build_context (+ compact), guarded_generate, format_response / generate_clarification, and a final trace-create upsert with output and metadata (citations, latency_ms, finish_reason). Falls back to the local JSONL collector at :3000 when Langfuse :3001 is unavailable. View via GET http://127.0.0.1:3000/observe/{request_id} or Langfuse UI :3001.
